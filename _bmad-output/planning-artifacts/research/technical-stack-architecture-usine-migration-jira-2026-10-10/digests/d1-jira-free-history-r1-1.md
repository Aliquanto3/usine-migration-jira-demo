## Bottom line

- **Q1, creating issues with past dates:** the REST API cannot do it (JRACLOUD-38572, open since 2014). The CSV External System Import (old experience, site admin) can set Date created and, if a Resolution is supplied, Date resolved. The JSON importer can also set `created`/`updated`. On Free, the site creator is the admin, so this path is available. I found no evidence of a plan-based restriction.
- **Q2, backdating status history:** CSV cannot import any history (JRACLOUD-64575). The JSON importer accepts a `history` array with past timestamps, but in Cloud the status items are flattened into generic entries that are not real status changes (JRACLOUD-81943, Long Term Backlog, unresolved as of 2026-04). They are therefore unreliable for an extractor that reads `changelog` status transitions or JQL `status CHANGED/WAS`. Treat **a realistic 8-week backdated changelog as not achievable natively in Jira Cloud**.
- **Q3, fallback:** use a hybrid. (a) A CSV or JSON import gives a backdated snapshot: created date, current status, resolution and resolved date. (b) Generate the 8-week transition history outside Jira as a synthetic, seeded changelog in the same JSON shape as `/issue/{key}/changelog`, and let the extractor merge it. Alternatively, store a "simulated date" in a custom field. (c) If you want real changelog entries, run a scheduled script that makes the transitions in real time over the coming weeks, so the history accumulates naturally. This is slow, and the real timestamps will not match a simulated calendar. For a public demo, (a)+(b) is the pragmatic choice. Document honestly that the history is simulated.
- **Q4, Free plan limits:** 10 users, 2 GB, low automation quota (150 steps, with inconsistent figures across Atlassian pages), no stated issue-count cap, full REST access. A script that authenticates with an API token is subject only to burst limits (around 100 POST/s per endpoint) and per-issue write limits, not the 65k points/hour quota. Throttle to a few requests per second and honour `Retry-After`. Tokens expire after at most 1 year, so plan for rotation.

## Leads not chased

- Whether the CSV importer's "Status" mapping on create writes a "Created → Status X" changelog entry, or only sets the status silently. My unverified belief is that no transition entries are created.
- Atlassian "Copy data" / Cloud-to-Cloud migration preserving history (mentioned in the community; it needs a source instance with real history, so it does not help here).
- Marketplace apps that claim to "inject" changelogs (a consulting agency did this, per a community snippet) and whether they work on Free (apps are limited on Free).
- Whether the "new import experience" (non-legacy) supports created date and history, or whether the old experience is scheduled for removal.
- The exact current automation quota for Jira Free (150 steps vs. 100 runs/month).

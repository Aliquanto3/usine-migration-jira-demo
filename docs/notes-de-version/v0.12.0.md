# v0.12.0 : conteneur, note de portage et préparation des répétitions

Dernière story bonus (8.3) : la Chaîne et l'interface web tournent dans une image conteneur, et une note décrit le portage vers Dataiku et Power Platform. Les répétitions chronométrées de la démo (7.12) sont outillées. Toutes les données sont fictives ou publiques.

## Contenu

- **Image conteneur (8.3)** : `Dockerfile` à la racine, basé sur l'image uv épinglée par digest. Il installe le projet avec `uv sync --locked`, sans le groupe `dev` ni le groupe `evaluation`. Le groupe `bonus` s'ajoute avec l'argument de build `AVEC_BONUS=1`. L'image tourne sous un utilisateur non root. Elle ne contient aucun secret : le `.env` est fourni au lancement et n'est jamais copié. L'image lance `usine ui` par défaut, et aussi `usine rapport` en Palier 1 quand le Journal est monté.
- **Réseau** : `usine ui` reste sur `127.0.0.1`. L'écoute sur `0.0.0.0` n'est acceptée qu'à l'intérieur d'un conteneur (`USINE_UI_HOTE`). Le port est publié sur la boucle locale de l'hôte seulement (`-p 127.0.0.1:8000:8000`).
- **Note de portage détaillée (8.3)** : `docs/portage-detaille.md`. Pour Dataiku et pour Power Platform, elle décrit le découpage des briques, la gestion des secrets et de la configuration, et les limites connues.
- **Contrôle avant répétition (7.12)** : `outils/controle_repetition.py` démarre `usine ui` en Mode repli. Il vérifie les sept écrans dans Edge headless : pas de « Chargement… », pas de bandeau d'erreur, blocs principaux visibles. Il vérifie aussi que les livrables se téléchargent.
- **Fiche de chronométrage (7.12)** : `demo/fiche-chronometrage.md`. Elle donne les tests manuels encore ouverts, les étapes du script avec leur temps cible et trois colonnes de répétition, dont une en Mode repli.

## Limites

- Image non construite sur le poste de développement, faute de Docker. Le build et un lancement réel restent à faire.
